# 검증 계획

## 목적

실제 기숙사 세탁기에 장치를 부착하지 않고도 데이터 수집, 상태 판정, 저장, 알림 흐름을 반복 가능하게 검증합니다. 현장 적용 가능성을 주장하기보다 프로토타입의 동작 범위와 한계를 수치로 기록하는 것이 목적입니다.

## 권장 시험 환경

우선순위는 다음과 같습니다.

1. 소유자에게 명시적인 허가를 받은 개인 세탁기
2. 운영자에게 명시적인 허가를 받은 시험용 세탁기
3. 소형 진동 모터와 금속판 또는 플라스틱 상자로 만든 실험 장치

공용 세탁기에는 허가 없이 센서를 부착하거나 주변 설비를 변경하지 않습니다.

## 데이터 수집 절차

1. 작동 전 정지 상태를 2~3분 수집합니다.
2. 세탁 시작, 본세탁, 헹굼, 탈수 시작과 종료 시각을 별도로 기록합니다.
3. 동작이 끝난 뒤 5분간 추가 수집합니다.
4. `http://localhost:8081/api/telemetry/export.csv`에서 데이터를 내려받습니다.
5. 센서 위치, 감도 조절 상태, 실험 장치, 네트워크 조건을 함께 기록합니다.

## 필수 시나리오

| 시나리오 | 기대 결과 |
| --- | --- |
| 작동 전 장시간 정지 | 세탁 시작 또는 완료 알림이 발생하지 않음 |
| 지속적인 약한 진동 | 동작 상태를 유지함 |
| 강한 진동 | 데이터가 정상 저장되고 동작 상태를 유지함 |
| 30초~2분의 중간 정지 | 완료로 오인하지 않음 |
| 문 닫힘과 같은 짧은 충격 | 새로운 세탁 주기로 오인하지 않음 |
| 정상 동작 후 장시간 정지 | 한 번만 완료 알림을 보냄 |
| Wi-Fi 또는 MQTT 단절 | 통신 장애를 완료로 오인하지 않음 |

## 평가 항목

- 실제 종료 탐지 여부
- 중간 정지에 대한 오탐 횟수
- 실제 종료부터 알림까지의 지연 시간
- 한 세탁 주기당 중복 알림 횟수
- MQTT 메시지와 DB 저장 건수의 차이
- 네트워크 복구 후 데이터 흐름 정상화 여부

## 현재 제한 사항

- 완료 판정은 연속 수신 구간의 무진동 시간을 사용하며 실제 세탁 단계는 구분하지 않습니다.
- 진행 상태는 DB에 복구하지만, 서버 중단·통신 공백 동안의 실제 진동은 알 수 없어 복구 후 새 관측 구간을 확보합니다.
- 발송 응답 유실이나 발송 중 프로세스 중단은 알림 확인 필요 상태로 남깁니다. [복구 안내](RELIABILITY.md)를 참고하세요.
- 로컬 10초 및 기본 180초 임계값은 실제 데이터 기반 최종값이 아닙니다.
- SW-420은 디지털 임계값 센서이므로 진동 크기의 정밀 측정 장비가 아닙니다.

## 완료 기준

다음 결과물을 남기면 프로토타입 검증을 완료한 것으로 봅니다.

- 하드웨어 및 전체 데이터 흐름 시연
- 최소 한 종류 이상의 허가된 진동 데이터셋
- 각 필수 시나리오의 결과 표
- 발견된 오탐과 원인 분석
- 실제 기숙사 적용 전에 추가로 필요한 검증 목록
